### D2 — Ambient-bytecode trap between two Makefile targets (CONFIRMED today)

Running `make check-fast` invokes Python without `-B`, creating
`scripts/__pycache__` — which the *next* `make pre-push-security` then
correctly rejects as ambient bytecode. A developer running the documented
targets in the natural order gets a confusing self-inflicted failure.
Recommended one-line correction (separate PR): export
`PYTHONDONTWRITEBYTECODE=1` in the check targets so validation never
poisons the publication gate. (CI already sets it at the workflow level.)

setup line in README/onboarding (docs-only PR).
