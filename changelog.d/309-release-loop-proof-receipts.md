### Changed

- Cut the merge-to-live loop for both sites without weakening a control. The promoter's launchd `StartInterval` moves from 900 to 300 seconds, and both sites' `OCIRepository` and `HelmRelease` reconcile at `1m0s` instead of `10m0s`. Every one of those is a read-only poll of already signature-verified state, so the shorter bounds add no credential, no inbound path and no object; a Flux `Receiver` would have added all three and is deliberately excluded. The cadence is pinned where it cannot drift: the constant, the emitted plist and the runbook's one sentence are compared to each other, `scripts/validate_signature_policy.py` states the site chart source's interval as an exact literal, and `scripts/validate_release_state.py` now pins reconciliation cadence PER release identity — one minute for the two sites, ten for the suspended connector — so widening either is a gate failure rather than an edit. Closes #309.
- Give a promotion pull request a receipt it EARNS rather than one it requests. After planning, each tick judges every open promoter pull request it keeps: no `snaraj-agent-reviews[bot]` comment already binds that head; every path the head changes against `main` is one the promoter's own `apply_promotion` writes — the permitted set is that function's return value from the re-derivation, never a list kept in the tool; and re-running the issue-195 acquisition ceremony from `main` in a detached read-only worktree re-renders the whole promotion surface, whose every blob is then compared to the head's by Git object id. All three hold and the reviewer App posts `VERDICT: APPROVE` at that exact head, validated by `scripts/validate_review_receipt.py` and with the live head re-read immediately before posting; a definitive failure of confinement or re-derivation posts `VERDICT: REQUEST-CHANGES` naming the proof and the mismatch. A refusal the tool cannot attribute to the pull request — registry, Release, cosign, network — is neither verdict: it is logged and the head is judged again next tick. `receipt` runs the same step alone under the same lock.
- Stop arming the cybersecurity lane on the promoter's own mechanical output. `REVIEW_LABELS` is `("requires-review",)` and `scripts/ready_check.py`'s `PROMOTER_TUPLE` drops `cybersecurity-review-requested` with it; the tier/review pair rule now applies to ordinary authors only, where it was written to apply, since the promoter's exact tuple already fixes both members. The security lane keeps reviewing every change to the promoter's CODE, which is where the risk lives, and AGENTS.md's promoter paragraph states the new rule: the receipt is earned by re-derivation and posted by the App from the tick, the promoter then flips ITS OWN promotion pull requests under the Ready rule's own evaluator (owner ruling 2026-09-04, the one tool-driven flip the contract permits; the coordinator flips everything else), and the owner alone merges.
- Make a stalled external call visible while it is stalling. Owner direction 2026-09-04, after one `cosign verify` held the full 600-second command bound and left a single refusal line ten minutes later while the next tick silently retried: every long call now logs `START <kind> <target> budget=<n>s` and `DONE <kind> <target> elapsed=<n>s`, and a failure puts the decision the tick took — `retry`, `refuse` or `skip-this-tick` — on the same line as its redacted reason, because the caller declares that decision once and every call under it reports the truth instead of a guess. Cosign gets its own short budget of 120 seconds with exactly one in-tick retry, so a Sigstore or registry stall costs a couple of minutes and a logged retry rather than a silent ten; both constants are named and pinned like the tick interval. Each proof logs its outcome and elapsed time, and every tick ends in one `SUMMARY` line — on every exit path, refusals included — naming each workload's verdict and each pull request it touched. `run_command` gains `quiet_output` for the one command whose stdout IS a credential, so a failing token helper can no longer put a token in the local log; a test asserts the token, `GH_TOKEN`, `Authorization` and the registry pull token appear in no logged line. The runbook's "Reading the log" lists every shape.
- State the actuals in every promotion pull-request body, so the accounting contract can be satisfied by a cut at all. AGENTS.md requires the commission to state an estimate and the body the actuals; a generated promotion body carried none, which is what refused the 0.1.73 promotion. `Workspace.numstat` measures files, additions and deletions from the index after `add -A` — the same rows for all three, never the length of `apply_promotion`'s returned path list, because a gate that rewrites a tracked file changes what the commit records without changing what the rewrite reported — and refuses a row it cannot measure, a binary path included. One rendered line naming the command that reproduces it reaches the commit message and the body alike, and a body may state it exactly once or the cut refuses. Carries the still-valid diff of PR #308 at 47e1a9ce (superseded) with its two review findings fixed: the live-cut fixture now makes the index and the reported path list disagree in count, so a body counting the tool's own list fails the oracle. Closes #307.
- Keep the reviewer App's token out of everything but one process's environment. The helper that mints it is named by `PROMOTER_RECEIPT_TOKEN_COMMAND`, never by a committed path, and the launchd installer plants that variable only when told to; unset, the receipt step reports itself unconfigured and composes nothing. The token is minted, held in one local name and handed to exactly one `gh pr comment` subprocess through its environment — never an argument, never a log line, never a file — and a test asserts all three. The App's actor identity is read from `scripts/ready_check.py` rather than copied, so the principal the receipt is posted by and the principal the Ready rule later looks for cannot drift apart. Path names from an untrusted head are sanitized and bounded before they can reach a public comment.
- The promoter's receipt now audits the pull request body and the head commit's message by re-composing both from the re-derived records; judges only a Draft that carries `requires-review`; counts only a validator-shaped App receipt as binding a head and re-reads novelty immediately before posting; retires that label with either verdict and finishes a retirement a failed tick left behind; and traces the tick's first fetch and cosign's version check like every other call.
- Every write the promoter makes against a pull request — the receipt post, the label retirement, the Ready flip — is bound to the exact head it evaluated: the head is re-read immediately before and after the write, a write whose head moved is undone (the flip un-flipped, the label put back), the base is compared live before the flip, and `scripts/ready_check.py` withholds while any comment by anybody but the review App is newer than the APPROVE receipt.
